# コーヒーレンス（Coffeerence）

ブリューイング競技の練習支援アプリ。限られた公式豆・練習時間・試行回数のなかで、

1. 何をもう試さなくてよいか
2. 次に何を試すか
3. 本番で何を死守するか
4. 2回の試技をどう賭けるか

を、感想ではなく推定で答えるための道具です。オフラインで動作し、データは端末の IndexedDB にのみ保存します（アカウント不要・クラウド同期なし）。

## 設計の芯

- **実験計画を自動生成する**: 1セッション1因子（OFAT）。水準・レプリケート・隠し重複・提供順をアプリが決める。
- **ブラインドを強制する**: 採点画面にはレシピ情報を出さない。正体はリビールまで開示しない。
- **自分の測定誤差 σ を測る**: 隠し重複ペアの採点差から σ を推定し、少ないうちは事前分布へ縮小する。σ を超えない差は「判定不能」と表示する。
- **後出しを封じる**: リビール後は採点を変更できない。削除・計画変更・中断は監査ログに残る。

## 主な機能

| 画面 | 内容 |
| --- | --- |
| ホーム | 今日やること、残り豆量、σ の状態 |
| セッション計画 | 因子と2水準を選ぶと、杯数・隠し重複・提供順を自動生成 |
| 抽出モード | 注湯タイマー、実測値（豆量/湯量/提出量/落ちきり/TDS）、150mL 判定、収率 |
| ブラインド採点 | 欠点チェック → 強度スケール → フレーバー再認（ダミー入り）→ 自信度 |
| 対比較 | 情報量が最大になるペアを提示。バランス・総合は比較でのみ取得 |
| リビール | 正体・隠し重複ペアの差・σ への寄与 |
| 分析 | 効果量と95%CI、探索の打ち切り判定、感度マップ、次セッション推奨 |
| 信頼度 | 項目別 σ、必要試行回数、ダミー選択率、推移律の破れ |
| レシピ確定・戦略 | 2回合計の期待値・分散・目標超過確率、外部ラベルによる校正 |
| 競技リハーサル | 準備7:00 → 競技7:00 → 審査3:00 の自動遷移、Wake Lock、通知音 |
| トレーニング | 三点識別（二項検定・3-up/1-down ステアケース） |
| 設定 | 大会定義、重み、豆残量、JSON/CSV 書き出し、監査ログ |

## アルゴリズム

- σ 推定: `σ̂ = sd(d)/√2`（d = 隠し重複ペアの採点差）。5ペア未満は事前分布 σ=1.0 へ縮小。
- 対比較: Bradley-Terry（MM 反復）。連結成分ごとに推定し、成分内で θ の平均を 0 に正規化。CI はブートストラップ。
- 効果量: 同一セッション内の水準差をブートストラップし、CI がゼロを跨げば「判定不能」。
- 必要試行回数: 検出したい効果量 δ（既定 0.5点）と σ から算出。
- 三点識別: 帰無仮説 p=1/3 の二項検定。2σ 未満は「まぐれの範囲」。
- 戦略: 2回合計を正規近似し、目標ライン超過確率で並べ替え。

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm test           # ユニットテスト（統計・計画・識別）
npm run lint       # oxlint
npm run typecheck  # tsc
npm run build      # 本番ビルド
```

## 投稿の判定

豆友の投稿は保存前に必ず判定を通す（利用者側の設定項目は無い）。本判定は OpenAI 互換の
moderation モデルで、API キーを静的サイトに置けないため `proxy/`（Cloudflare Workers）を経由する。
プロキシの URL は Actions 変数 `VITE_MODERATION_ENDPOINT` で渡す。到達できないときは
`src/lib/moderation.ts` の規則判定だけが働く。手順は `proxy/README.md` を参照。

## スコープ外（v1）
